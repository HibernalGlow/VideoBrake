# 新工作流程说明

## 概述

新工作流程采用**一次处理、一个 JSON** 的设计思路，使用时间戳区分不同的处理批次。整个流程分为三个步骤：

1. **扫描 (Scan)** - 扫描目标文件夹，提取关键帧，生成 JSON 文件
2. **识别 (Identify)** - 使用 Gemini AI 批量识别角色和原作，更新 JSON 文件
3. **处理 (Process)** - 根据 JSON 文件中的角色信息，移动或复制视频文件

## 工作流程详解

### 步骤 1: 扫描文件夹

```bash
# 方式 1：命令行模式
python cli.py scan <目标文件夹路径>

# 方式 2：交互式模式
python cli.py
# 选择 1 - 扫描文件夹
```

**功能说明：**

- 扫描指定目录下的所有一级子文件夹
- 对每个文件夹中的第一个视频文件提取关键帧（作为代表）
- 关键帧保存到 `output/frames_<时间戳>/文件夹名/` 目录
- 生成 `output/scan_<时间戳>.json` 文件记录所有信息

**输出示例：**

```
output/
├── scan_20231214_120000.json    # 扫描数据文件
└── frames_20231214_120000/      # 关键帧目录
    ├── 文件夹1/
    │   ├── frame_01.webp
    │   └── frame_02.webp
    └── 文件夹2/
        └── frame_01.webp
```

**JSON 文件结构：**

```json
{
  "timestamp": "20231214_120000",
  "target_dir": "D:\\Videos\\Cosplay",
  "folders": [
    {
      "folder_name": "某个文件夹",
      "folder_path": "D:\\Videos\\Cosplay\\某个文件夹",
      "video_count": 3,
      "video_files": ["某个文件夹/video1.mp4", "某个文件夹/video2.mp4"],
      "representative_video": "某个文件夹/video1.mp4",
      "frames": [
        "frames_20231214_120000/某个文件夹/frame_01.webp",
        "frames_20231214_120000/某个文件夹/frame_02.webp"
      ],
      "frame_count": 2,
      "status": "pending",
      "character_info": null,
      "notes": ""
    }
  ]
}
```

### 步骤 2: 批量识别

```bash
# 方式 1：命令行模式
python cli.py identify --scan-file scan_20231214_120000.json

# 方式 2：交互式模式
python cli.py
# 选择 2 - 批量识别
```

**功能说明：**

- 读取扫描文件中的所有文件夹信息
- 使用 Gemini AI 识别每个文件夹的角色和原作
- 自动更新 JSON 文件，填写 `character_info` 字段
- 支持断点续传（跳过已识别的项）
- 每识别一个自动保存，防止意外中断丢失进度

**识别后的 JSON 结构：**

```json
{
  "folder_name": "优菈_原神_舞蹈",
  "status": "identified",
  "character_info": {
    "character": "优菈",
    "source": "原神"
  }
}
```

**高级选项：**

```bash
# 重新识别所有（包括已识别的）
python cli.py identify --scan-file scan_xxx.json --no-skip

# 不自动保存，全部识别完成后再保存
python cli.py identify --scan-file scan_xxx.json --no-auto-save
```

### 步骤 3: 批量处理

```bash
# 方式 1：命令行模式（测试模式）
python cli.py process --scan-file scan_20231214_120000.json --dry-run

# 方式 2：正式处理（移动文件）
python cli.py process --scan-file scan_20231214_120000.json --mode move

# 方式 3：复制文件
python cli.py process --scan-file scan_20231214_120000.json --mode copy

# 方式 4：交互式模式
python cli.py
# 选择 3 - 批量处理
```

**功能说明：**

- 根据 JSON 文件中的角色信息，将视频文件移动或复制到对应的角色文件夹
- 支持测试模式（dry-run），不实际移动文件，仅显示操作预览
- 自动创建目标文件夹
- 处理文件重名问题（自动添加序号）
- 未识别的视频移动到"未识别角色"文件夹

**处理结果：**

```
目标目录/
├── 优菈_原神/
│   ├── video1.mp4
│   └── video2.mp4
├── 2B_尼尔自动人形/
│   └── video3.mp4
└── 未识别角色/
    └── unknown_video.mp4
```

## 命令参考

### 扫描命令 (scan)

```bash
python cli.py scan <目标文件夹> [选项]

选项：
  --output DIR     输出目录（默认: output）
  --limit N        限制处理数量
```

### 识别命令 (identify)

```bash
python cli.py identify --scan-file <扫描文件> [选项]

选项：
  --scan-file FILE    扫描文件名（必需）
  --output DIR        输出目录（默认: output）
  --no-skip           重新识别所有（包括已识别的）
  --no-auto-save      不自动保存，全部识别完成后再保存
```

### 处理命令 (process)

```bash
python cli.py process --scan-file <扫描文件> [选项]

选项：
  --scan-file FILE    扫描文件名（必需）
  --output DIR        输出目录（默认: output）
  --mode MODE         处理模式：move（移动）或 copy（复制），默认 move
  --dry-run           测试模式，不实际移动/复制文件
```

## 与旧工作流程的对比

### 旧工作流程

1. `prepare` - 提取每个视频的关键帧
2. `generate-prompt` - 生成识别指令
3. **手动使用 Gemini CLI 识别**
4. `merge` - 合并识别结果
5. `organize` - 整理视频文件

**问题：**

- 每个视频单独处理，文件数量多
- 需要手动操作 Gemini CLI
- 多个 JSON 文件，管理复杂

### 新工作流程

1. `scan` - 扫描所有文件夹，提取代表性关键帧
2. `identify` - **自动**使用 Gemini API 批量识别
3. `process` - 根据单个 JSON 文件处理所有视频

**优势：**

- ✅ 一次处理，一个 JSON 文件
- ✅ 使用时间戳区分批次
- ✅ 自动化识别，无需手动操作
- ✅ 支持断点续传
- ✅ 更简洁的工作流程
- ✅ 按文件夹而非单个视频处理，更高效

## 手动编辑 JSON

如果 AI 识别有误，可以手动编辑 JSON 文件：

```json
{
  "folder_name": "某文件夹",
  "status": "identified", // 改为 identified 表示已识别
  "character_info": {
    "character": "修正后的角色名",
    "source": "修正后的作品名"
  }
}
```

也可以设置为跳过：

```json
{
  "status": "skipped", // 设为 skipped 表示跳过处理
  "character_info": null
}
```

## 完整使用示例

```bash
# 步骤 1: 扫描文件夹
python cli.py scan D:\Videos\Cosplay

# 输出：生成 output/scan_20231214_120000.json

# 步骤 2: 识别角色
python cli.py identify --scan-file scan_20231214_120000.json

# 等待识别完成...

# 步骤 3: 测试处理（预览）
python cli.py process --scan-file scan_20231214_120000.json --dry-run

# 步骤 4: 正式处理（移动文件）
python cli.py process --scan-file scan_20231214_120000.json --mode move

# 完成！
```

## 注意事项

1. **时间戳唯一性**：每次扫描都会生成新的时间戳，确保不同批次不会冲突
2. **文件夹层级**：扫描只处理一级子文件夹，不递归扫描
3. **代表性视频**：每个文件夹只选择第一个视频提取关键帧作为代表
4. **断点续传**：识别过程支持中断后继续，已识别的项会被跳过
5. **测试先行**：建议先使用 `--dry-run` 测试，确认无误后再正式处理
6. **备份重要数据**：移动模式会实际移动文件，建议先备份或使用复制模式

## 故障排除

### 识别失败

- 检查 Gemini API 配置
- 查看是否超出 API 配额
- 检查网络连接

### 文件未移动

- 确认使用的是正确的 scan 文件
- 检查 status 是否为 "identified"
- 使用 `--dry-run` 查看详细信息

### JSON 文件损坏

- 使用文本编辑器检查 JSON 格式
- 确保所有引号、括号匹配
- 可以使用在线 JSON 验证器检查
